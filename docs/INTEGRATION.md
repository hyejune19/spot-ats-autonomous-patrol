# 통합 설계와 구현 근거

## 하나의 프로젝트로 구성하는 기준

SPOT+ATS는 사족보행 이동 플랫폼에 ATS(Auto Targeting System)의 2축 기구를 결합하고, 인식 결과를 순찰 임무에 사용하는 프로젝트이다. 개발 디렉터리별로 결과를 나열하지 않고 이동·관측·인지·임무의 기능 경계로 구성한다. 동일한 역할의 구현이 여럿이면 실행 검증 결과와 인터페이스 호환성을 기준으로 하나를 선택한다.

| 기능 | 선택한 구현 | 선택 근거 |
|---|---|---|
| 보행 | ATS 탑재 모델에 맞춘 Isaac Lab 정책 | 탑재 질량을 포함하며 학습·실행 관절 순서를 일치시킨다 |
| 물리 실행 | Isaac Lab 환경을 통한 Isaac Sim 실행 | 학습에 사용한 액추에이터와 관측 48차원·행동 12차원의 계약을 보존한다 |
| 통합 진입점 | 이 저장소의 `scripts/run_unified.py` | 보행·ATS 제어·센서 발행·기록을 같은 물리 시간축에서 수행한다 |
| ATS | joint1·joint2 위치 목표 + 속도 명령 적분 | 보행 정책의 12개 다리 관절과 제어 대상을 분리한다 |
| 통신 | ROS 2 Humble / DDS | Isaac Python 3.11과 시스템 ROS Python 3.10을 프로세스 경계로 분리한다 |
| 이동 계획 | Nav2 | 지도·위치·경로·속도 명령을 단계별로 관찰할 수 있다 |
| 객체 인식 | 로컬 YOLO 추론 | 카메라 영상에 대한 실제 추론 결과를 사용한다 |
| 시각화 | Isaac Sim + RViz + 기록 기반 설명도 | 외형, 센서 관측, 경로 계획의 의미를 각각 설명한다 |

## 기구와 제어

Spot의 네 다리는 각각 세 개의 구동 관절을 가진다. 다리 제어는 총 12개 관절이다. ATS는 회전 관절 joint1과 joint2를 추가하여 총 14개 구동 관절이 된다. 고정 결합부와 링크의 수는 구동 관절 수와 다르다. 실제 실행에서 읽은 관절·링크 이름은 결과 JSON을 기준으로 한다.

ATS 원본 URDF의 joint1은 continuous, joint2는 revolute이다. joint2의 원본 범위는 −1.57~0 rad이다. URDF 축 벡터는 각 관절의 로컬 좌표계 기준이므로 그림에 그대로 세계축으로 표시하지 않는다. 통합 실행기는 로드된 물리 모델의 관절 제한을 읽어 목표를 제한한다. 다리 관절의 목표는 학습 정책이 계산한다.

## 센서 해석

선택한 LiDAR 구현은 창고의 직육면체 장애물과 광선의 교차를 계산하는 해석적 센서이다. 2D는 수평 360개 광선, 3D는 수직 16채널과 수평 2° 간격을 사용한다. RTX 광학 센서의 재질 반사·다중 반사·잡음을 재현하지 않는다. 등록된 창고 상자와 바닥을 관측하므로 사람 검출과 동적 장애물 검증에는 별도 확장이 필요하다.

`/odom`은 시뮬레이터의 물리 상태를 바탕으로 한다. 실제 로봇의 휠·다리 오도메트리 추정 오차를 입증하는 자료가 아니다. IMU 역시 현재 발행 항목과 프레임을 확인해야 하며 실제 센서의 바이어스·노이즈 검증과 구별한다.

## 코드와 자산의 경계

외부 ATS 기반 구현과 모델은 로컬 `SPOTATS_WORKSPACE`에 유지한다. 공개 저장소의 통합 실행기는 그 모듈을 의존성으로 불러온다. 공개 저장소만 복제하면 외부 모델과 정책이 자동으로 제공되는 구조가 아니다. USD·정책 체크포인트·강의 PDF·인증 환경 파일은 배포하지 않는다.
